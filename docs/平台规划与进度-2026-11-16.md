## 2. 不可动摇的决策

改这些之前先重新讨论，不要在新对话里"顺手优化掉"：

| # | 决策 | 原因 |
|---|---|---|
| 1 | **编辑器归专业工具，平台只做「存 / 跑 / 比」** | 已经论证过：自研编辑器是无底洞，收益为零 |

**关键机制（改代码前必须知道）**：

- **存储**：sql.js 内存数据库，每次写盘都是**整库重写**（tmp + fsync + rename，400ms 防抖）。所以**大结果、执行日志、响应体绝对不能进库**，只能存摘要。
- **Schema 演进**：改字段 → 加 `SCHEMA_VERSION` 并在 `MIGRATIONS` 里加一步，不要直接改表结构。迁移前自动备份到 `backups/`。
- **加密**：`safeStorage`（Windows DPAPI）加密密码字段，前缀 `enc:` / `raw:`。**DPAPI 绑定当前 Windows 用户**，跨机器/跨账户解不开。
- **数据目录**：`TT_DATA_DIR` > portable（`PORTABLE_EXECUTABLE_DIR` + 旁边有 `portable.marker`）> `%APPDATA%\测试工作台`。默认落在 AppData。
- **单实例锁** + 托盘常驻 + 闲置自动锁定（需先设 PIN）。

### 核心结论（几轮讨论后的最终版，别再推翻）

> **「接口绑定」不属于用例内容，属于两份资产之间的映射关系。**

理由（按重要性）：
1. **用例先于接口**：开完需求会就产用例，那时接口还不存在、路径还没定。让用例写一个当时不存在的路径是逻辑倒挂。
2. **一个用例对多个接口**（登录→查单→下单），写在 md 里要三行且全路径。
3. **历史 2865 条用例不可能补**，规则一旦强制就等于给自己判死刑。
4. **路径会变**（重构路由），映射表改一条；写死在 md 里就是灾难。

### 数据模型

```sql
CREATE TABLE IF NOT EXISTS case_api_links (
  id          INTEGER PRIMARY KEY AUTOINCREMENT,
  file_path   TEXT NOT NULL,   -- 用例文件相对路径
  case_title  TEXT NOT NULL,   -- 用例标题（解析时用来回找，标题比序号稳定）
  case_index  INTEGER,         -- 冗余，仅用于同标题消歧
  api_id      TEXT NOT NULL,   -- records.id（apis 集合里的记录）
  source      TEXT,            -- manual
  created_at  INTEGER
);
CREATE UNIQUE INDEX IF NOT EXISTS idx_link ON case_api_links(file_path, case_title, api_id);
```

- 关联是软键：解析时按 `file_path + case_title` 回找当前用例。**用例被改名/删除 → 显示「已失效」而不是报错**，可以一键清理。
- `SCHEMA_VERSION` 从 2 升到 3，在 `MIGRATIONS` 里加一步建表。

### 交互

- 接口记录详情页底部：「关联用例 [n]」按钮 → 弹窗搜索用例（搜标题）→ 多选 → 保存
- 用例详情抽屉：新增一块「关联接口」，显示 method + url，点击跳到对应接口记录
- **全部用 LEFT JOIN**，空关联不报错、不显示警告

> 0.7.0 落地说明：关联是**单独按 `api_id` / `file_path+case_title` 查出来**，再由渲染层把 api_id 映射成记录
> （接口记录最多几千条，一次取回够用），等价于 LEFT JOIN 语义，没在 SQL 里硬 JOIN —— 少一层联表，也方便单独缓存。
> 「已失效」是渲染层判断的：接口侧看 api_id 还在不在 `api` 记录里，用例侧看软键还在不在当前扫描结果里。

### 三条设计红线（专门为「我懒得勾」准备）

1. **不做全局「待关联 2865 条」待办条** —— 那是债务清单，用户迟早当噪音关掉
2. **不做「⚠ 未关联」红字警告** —— 没关联是合法状态
3. **候选只以灰字出现，点开才升级为强关联** —— 不点不影响任何主流程

### 三种「客观上认领不了」，都不算失败

| 情况 | 正确做法 |
|---|---|
| Apifox 里找不到这个路径（五个 login / 没发布到公开目录） | 手动建一条**占位接口**填 path + 备注，先关联；等规范了再同步覆盖 |
| 用例写得太抽象（"验证登录功能正常"） | 本来就不该挂单个接口（它可能是 UI/场景用例），不挂是**正确**的 |
| 接口太多，只关心 15 个 | 只认领要反复测的。判断标准：**会变 × 不熟** |

>    老记录取出来是空值，界面正常显示（有测试覆盖）。`keepUnknownFields` 仍然保护未知字段。
> 2. **`params` 排序是 path → query → header → cookie**（原文没规定），且必填带 `*`、带类型和描述。
> 3. **`syncedAt` 用 epoch 毫秒存**，渲染层格式化成 `YYYY-MM-DD HH:mm`（列表排序/导出都不受影响）。
>
> **额外做了一件原文没写的**：`source` 字段默认 `'manual'`（新记录自动标「手录」），同步来的标「Apifox」，
> 详情标题旁有 tag，一眼看出这条是镜像还是自己写的。

### 为什么做

开发在 Apifox 里建好接口，口头告诉你"XX 路径的 login 接口，可以测了"。现状是你得打开 Apifox 翻目录找。镜像把接口"搬"进工作台，加上 Apifox 永远不会有的东西：**你自己的备注层**。

### 数据来源

Apifox 导出 `openapi.json`（Apifox 支持导出 OpenAPI 3）。同步入口：接口记录页右上角「从 Apifox 同步」→ 选文件。

### 数据模型（**扩展现有 `apis` 集合，不新建集合**）

现有字段：`name / method / url / headers / body / note`
新增字段（**实际没走 migrations**，只加 JSON 键，见上面的差异说明）：
- `source`（manual / openapi，默认 manual）、`syncedAt`（epoch 毫秒）
- `module`（Apifox 目录 = 第一个 tag，没有就「未分组」）、`summary`（接口描述，常为空 → 完整度标记）
- `params`（`path/query/header` 摘要，每行 `位置: 名字[*] (类型) 描述`）、`reqSchema`、`respSchema`（JSON 字符串，$ref 已内联，超 6000 字符截断）
- `completeness`（missing-desc / missing-example / ok）
- **`myNote`（你自己的备注层，同步永不覆盖）← 这是整个模块最值钱的字段**

### 同步规则

- **幂等 upsert**：唯一键 `method + url`（`apiKey()` 统一大小写、去尾斜杠）。重复导入不产生重复记录。
- **只覆盖 OpenAPI 来的字段**，`myNote`、`tags`、`favorite`、`headers`、`body`、`note` 一律不动（有 4 条测试盯着）。
- 描述/参数/Schema 都没变的那条算「跳过」，不刷 `updated_at`（否则同步一次全库都变「刚改过」）。
- 整个同步包在一个事务里，中途抛错全部回滚。
- 摘要卡片：新增 n / 更新 n / 跳过 n / 缺描述 n（+ 重复/残缺条目按需提示）。
- 保留**手动新增接口**入口（对应上表"占位接口"场景）；手写记录被同步认领时只补镜像字段，备注留着。

### 明确不做

- ❌ 平台内调试器（复制 cURL 粘到 Apifox 发，理由：cookie/登录态/AI 断言 Apifox 已经做完了）
- ❌ jmx 编辑、脚本编辑
- ❌ 把响应体存库（只在界面临时显示）

> **状态：已完成（2026-11-03，实际 0.3 天左右）。** 落地位置：`electron/openapi.js` 的 `diffApi` + `paramSpec` 快照、

> `RecordDetail` 的 `type: 'change'` 渲染 + `hideInDetail` / `hideEmpty` 支持、`CasePage` 支持按软键直接打开用例。
>
> **变更判定口径（这是这块的核心，改之前先看）**：
>
> | 算变更 | 不算变更 |
> |---|---|
> | 必填参数增删（含「可选 → 必填」这种最危险的） | 描述/说明文案 |
> | 参数类型变化 | 参数顺序 |
> | 请求体：必填清单、顶层字段增删、类型变化 | example / 注释 |
> | 响应体：顶层字段增删、类型变化（响应是数组会钻一层 items） | 目录 tag、名称 |
>
> **几个刻意的决定**：
> 1. **不做「已读/未读」状态**。多余的状态就是多余的一处 bug，「上次同步」永远指最近一次；下次同步没变，
>    提醒自己消失。
> 2. **老记录没有快照时不算变更**。手写接口第一次被同步，没有可比对象，报「全变了」只会让提醒变噪音。
> 3. **单条接口最多列 8 项变更**，防一个大字段改动刷屏。
> 4. **提醒要能被重新打开**：关掉卡片后，接口记录页头有「上次同步变更 · n」，数据在 meta 里，不额外建表。
> 5. 影响面只到「挂了哪些用例」，**不做到「这些用例的哪一步会挂」** —— 那需要语义理解，成本是另一个量级。

## 7.3 已交付 E：测试执行账本（0.12.0）

> **状态：已完成（2026-11-03，实际 0.5 天）。** 落地位置：`shared/collections.js` 的 `runs` 集合 + `onlyFor` 开关、

> 再封一层 JMeter 或者自研 runner 就是**重写一个更差的 Apifox**。
> 但 Apifox 有个永久缺口：**报告会被下一次跑覆盖**。「这个接口历史上压过几次、最好 320 TPS、这次变没变慢」它不留 —— 这才是平台该管的。
>
> **三档的界限（档 2/3 未批准）**：
>
> | 档 | 内容 | 成本 | 状态 |
> |---|---|---|---|
> | 1 记账 | 手填结果 / 指标 / 结论 + 报告链接，挂接口，详情里看最近 3 次 | 0.5–1 天 | ✅ 0.12.0 |
> | 2 关联 | 把 Apifox 的测试场景登记成只读记录，接口 / 手工用例 / 场景三方互链 | 1–1.5 天 | 未批准 |
> | 3 触发归档 | 填 CLI 路径 + Access Token，一键跑场景，解 JSON 报告写执行记录 | 1.5 天 + 0.5 天探针 | 未批准（先探针：内网能不能连 Apifox） |
>
> **几个刻意的决定**：
> 1. **结果只有「正常 / 异常 / 未判定」**，不用「通过 / 失败」—— 压测说「达标」、接口测试说「通过」，一套词覆盖两边，
>    而且**允许空着**（先记指标，结论回头再补）。
> 2. **字段按类型换，不是加两套表单**。用 `onlyFor: { kind: 'perf' }` 一个开关，表单和详情各过滤一次，
>    用户看不到与自己无关的字段（压测不会看到「通过多少条」）。
> 3. **摘要行缺什么跳过什么**，不补破折号。`400 TPS` 比 `400 TPS · — · —` 好看，也更诚实。
> 4. **报告只存链接不存内容**：整库重写是 sql.js 的持久化方式，存 HTML 报告会把库撑坏（同 0.8.0 不存响应体）。
> 5. **空态是灰字一句话**：「还没跑过 —— 在 Apifox 跑完记一笔，以后就能在这看到它挂没挂」。不报警、不算待办。

## 11. 已知坑（踩过的，别再踩）

### 11.1 最近的坑（按时间倒序，每次任务收尾往里加）

**2026-11-03 · v0.12.0 测试执行账本**

- 🟡 **`onlyFor` 的字段隐藏要同时改三处**：编辑表单、详情、保存前的必填校验。漏掉最后那个，用户会被一个看不见的
  「必填」卡住保存（这次一开始就漏了，`save()` 里的必填循环还在遍历全部字段 → 改成 `visibleFields(conf.fields, data.kind)`）。
- 🟡 **列表页的 `link` 字段原本会直接渲染 id**：`renderListField` 的默认分支 `String(value)`。加记录前先在
  `renderListField` 里补 `link → linkMap[value]`（以及顺手补了 `datetime → fmtTime`），否则「关联接口」那列显示 `p1`。
- 🟢 **预填新增的窍门**：`RecordForm` 的 `save()` 用 `id: record && record.id`，所以传一个**没有 id 但带 data 的草稿对象**
  就是「新建 + 预填」。不用给表单加 initialValues props。
- 🟢 **跨集合跳转沿用 openRecordId 的模式**：路由塞 `logFor` → 目标页 `useEffect` 消费后立刻 `onLoggedRun()` 清掉，
  否则关掉表单再切页面会又弹一次。
- 🟡 **数字字段存成 number 而不是字符串**：`type: 'number'` 在表单里 `Number()` 一下，`runLine` 里再用 `Number.isFinite`
  兜住老数据（手填过的字符串），否则 `'320' + ' TPS'` 和 `320 + ' TPS'` 两种来源会算出不同格式。

**2026-11-03 · v0.11.0 目录两层树**

- 🟡 **侧栏宽度是共用的**：`.tag-panel` 同时被接口记录页用，直接改宽度会连带改到那边的标签栏。做法是给用例页
  加修饰类（`.tag-panel.dir-tree`）单独加宽，别动基类。
- 🟡 **长文件名在 178px 的侧栏里没救**：`TC_商家门户重构_第三次迭代_混合_2026_10_08_修正版.md` 有 33 个字符，
  等宽 11.5px 一行也就能放 15 个。有效组合是「加宽到 236 + 允许两行 + `-webkit-line-clamp: 2` + `title` 给全路径」，
  只用其中任一个都不够（实测：两行后最长的那个文件名完整显示，`scrollHeight === clientHeight`）。
- 🟡 **`localeCompare(zh-Hans-CN)` 是按拼音排的**：`TC_洗车卡券_核销…` 排在 `TC_新人券模块…` 前面（洗 xi < 新 xin），
  写断言时别按「看起来的顺序」写，要么按集合判断、要么自己算一遍。
- 🟢 **展开状态要跟着选中走**：只点目录名而不展开，用户会觉得「点了没反应」。选目录时自动 `expanded.push`，
  caret 只管纯展开/收起（`e.stopPropagation()`，否则点箭头等于点行）。

**2026-11-03 · v0.10.1 分页 / 占位符**

- 🔴 **antd Table 的 `pagination` 不写 `current` 就是非受控，换数据源不会复位**。用户实际踩到的：
  「需求 A 翻到第 2 页 → 切需求 B」停在 B 的第 2 页（B 只有 1 页时 antd 会夹到第 1 页，看着像自己好了；
  B 有 ≥2 页就直接错位）。**规矩：凡是有筛选/切换的表格，一律受控 + 在筛选依赖变化时 `setPage(1)`**，
  再用 `Math.min(page, Math.max(1, Math.ceil(n / size)))` 兜住越界（数据被删到不满一页时不会白屏）。

### 11.2.1 打包 / 依赖

#### 1. 本地测试全绿，打包后启动崩溃：`Cannot find module 'xxx'`

**现象**

```
A JavaScript error occurred in the main process
Error: Cannot find module '@xmldom/xmldom'
Require stack:
- ...\resources\app.asar\electron\jmx.js
```

本地 `node scripts/test-jmx.cjs` 39 项全过，打包后一启动就崩。

**根因**

`@xmldom/xmldom` 不在 `package.json` 的 `dependencies` 里。它只是 `plist`（electron-builder 的间接依赖）带进来的，在 `package-lock.json` 里被标成 `dev: true`。

electron-builder 的打包规则：**只收 `dependencies` 里的生产依赖**，`dev: true` 的包一律不进 asar。

所以测试环境和运行环境根本不是同一套依赖图——`node_modules` 里恰好有，不代表 asar 里有。

**怎么防**

1. **任何新增的 `require`，先确认它在 `dependencies` 里**，不能靠间接依赖。间接依赖最危险：`npm install` 不报错，只在用户机器上炸。
2. 加完依赖跑一次 `npm install --package-lock-only`，然后确认 lockfile 里没有 `dev: true`：
   ```powershell
   node -e "const l=require('./package-lock.json');console.log(l.packages['node_modules/@xmldom/xmldom'].dev)"
   # 期望输出 undefined，不是 true
   ```
3. 判断标准：**这个包在运行时（不是构建时）被 require 吗？** 是 → `dependencies`；只在 esbuild / electron-builder 阶段用 → `devDependencies`。

**怎么验证（关键）**

不要只检查「asar 里有没有这个字符串」——源码当然有。要**从 asar 里真实加载并跑一遍**：

```powershell
cd Project\test-tool
$env:ELECTRON_RUN_AS_NODE="1"
& ".\node_modules\electron\dist\electron.exe" "D:\AI_Workspace\_scratch\2026-11-16\verify-asar-load.cjs"
```

脚本内容：`require(path.join(ASAR, 'electron', 'jmx.js'))` 然后跑一次 `scanJmx`。输出 `RESULT: PASS` 才算真的没问题。

> 普通 `node` 不支持 asar，必须用 Electron 本体；GUI 在沙箱里起不来，所以用 `ELECTRON_RUN_AS_NODE=1` 让它以 Node 模式跑。

**历史**

- v0.16.0 踩中，v0.16.1 修复。`sql.js` 一直没事是因为它本来就在 `dependencies` 里。

### 11.2.2 数据 / 存储

#### 4. 清除数据后「数据自己回来了」

**根因**

存储层每次改动都延迟 400ms 整库重写（防抖）。直接删 `data.db` 的话，400ms 后内存里的旧数据会被原封不动写回去。

**怎么防**

删库前必须先 `clearTimeout(saveTimer)`，再删文件、重建空库、立即落盘。

**怎么验证**

测试里专门有一条：清除后**等 700ms 再查一次**，确认仍然是空的。

```js
await new Promise((r) => setTimeout(r, 700));
const countsLater = await call('records:counts');
check('过了防抖窗口数据也没有自己回来', Object.keys(countsLater).length === 0);
```

#### 5. 导入 JSON 后用例↔接口关联全断

旧版 `importAll` 不保留原 `id`，重新生成。而关联表 `case_api_links` 是按 `api_id` 挂的，id 一变就全悬空。

**怎么验证**

`test-main.cjs` 里：清空关联 → 导入 → 确认关联条数恢复。

#### 19. Windows 上 `spawn` 一个 `.bat` 会抛 `EINVAL`

**现象**

点「启动 JMeter」报 `spawn EINVAL`，而 `jmeter.bat` 明明存在、手动双击也能跑。

**根因**

Node 从 **CVE-2024-27980** 修复后，**禁止直接执行批处理文件**（`.bat` / `.cmd`），必须通过 shell 或 `cmd.exe`。这是安全限制，不是路径问题。

实测对照（Node v22.22.0 / Windows）：

| 写法 | 结果 |
|---|---|
| `spawn('D:\\...\\jmeter.bat', [])` | ❌ THROW EINVAL |
| `spawn(bat, [], { shell: true })` | ✅ OK |
| `spawn('cmd.exe', ['/c', bat])` | ✅ OK |
| `spawn('C:\\Windows\\System32\\cmd.exe', [...])` | ✅ OK（exe 不受限） |

**怎么防**

1. Windows 上启动 `.bat` / `.cmd` 一律用 `shell: true`（或 `cmd /c`）
2. 用 `shell: true` 时**路径必须自己加引号**，否则含空格/中文的路径会被拆成多个参数：
   ```js
   const cmd = '"' + bat + '"' + (jmxFile ? ' -t "' + jmxFile + '"' : '');
   spawn(cmd, { shell: true, detached: true, stdio: 'ignore' });
   ```
3. **错误码要翻译成人话**：`EINVAL` / `ENOENT` / `EACCES` 各给一条可操作提示，别把原始错误甩给用户

**怎么验证**

```js
// 探针：确认哪种写法能起
spawn(bat, [], { shell: true }).on('spawn', () => console.log('OK'));
```

#### 20. JMeter 的 `pct1/pct2/pct3` 不是固定的 P90/P95/P99

**现象**

`statistics.json` 里 `pct2ResTime = 5.35`，但从 jtl 自己算 P95 是 `4`。差得不多但确实不一致。

**根因**

JMeter 的分位由 `jmeter.properties` 里的 `aggregate_rpt_pct1/2/3` 决定，**用户可改**。默认是 90/95/99，但改过之后 `pct2` 就不是 P95 了。你的这份报告明显不是默认配置（`pct3=87` 等于 max）。

**怎么防**

**分位一律从 jtl 自己算，不信 statistics.json 的 pct 字段。**
`statistics.json` 只取无歧义的：`sampleCount` / `errorCount` / `errorPct` / `throughput`。

**怎么验证**

同一份数据两条路径对比：jtl 算出的 P95 和 statistics 的 pct2 应该一致；不一致就说明配置被改过。

---

#### 21. `html-report` 子目录会被误当成独立跑批

**现象**

扫描报告根目录时，`压测结果/` 和 `压测结果/html-report/` 都被识别成跑批，后者只有 `statistics.json` 没有 jtl，导致 P95 为 null。

**根因**

`html-report` 是 JMeter `-e -o` 生成的附属产物，和父目录的 `result.jtl` 是**同一次跑批**，不是两次。

**怎么防**

扫描时跳过名为 `html-report` 的子目录。判断标准：**这个目录里有独立的 jtl 吗？** 没有就是附属产物。

---

#### 22. 自动探测到了，但没落盘 → 用户以为没生效

**现象**

设置页「JMeter 路径」显示为空，用户以为自动探测失效了。实际 `jmx:scan` 返回的 `jmeter.found = true`。

**根因**

`detectJmeter()` 只在内存里返回路径，没写回 `settings`。而设置页读的是 `settings.jmeterPath`，所以永远是空。

**怎么防**

探测到就 `settings.jmeterPath = c; saveSettings()`。另外探测逻辑要放在**模块级**（不是 `registerIpc` 内部），这样 `app:init` 也能触发一次——否则用户不点「重新扫描」就永远看不到。

**怎么验证**

```js
const init = await call('app:init');
check('自动探测的 jmeterPath 已写回设置', init.settings.jmeterPath.includes('jmeter.bat'));
```

## 附录 A：用例解析器规则速查（改 parser 时看这里）

文件：`electron/cases.js`

- 层级判定：文件里**存在任意 `####`** → 用例层级 = 4（H2 模块 / H3 分支 / H4 用例）；**没有** → 用例层级 = 3（H2 模块 / H3 用例）。这样兼容老文件。

- 段落标签正则：`^\s*[-*]\s*(\*\*)?(前置条件|前置|操作步骤|操作|步骤|预期结果|预期|备注|检查项)(\*\*)?\s*[：:]\s*(.*)$` → 映射到 `pre / steps / expects / notes / checklist`
- 检查项：`^\s*[-*]\s*\[([ xX])\]\s*(.*)$`，`depth` = 前导空格数 / 2（上限 3）
- 断言迹：任何含 `断言迹：` 的行，按 `｜` 或 `|` 切分，每段 `维度:内容` → `{dim, text}`；顺手剥掉 `[覆盖 ...]`

- 标签：标题里 `[...]` 提取，`RISK_RE`（🔴🟡🟢/高/中/低）→ `risk`，`CATS`（冒烟/功能/异常/边界/兼容/性能/安全/高级/回归/数据/接口/UI）→ `type`，`🛤️` → `corePath`
- 文件过滤：`dir` 以 `_` 开头跳过；文件名匹配 `(评审报告|评审基准|评审意见|检查报告|迁移报告|差异比对|台账|_diff)` → 归为 doc
