# 测试工作台

> 一个**只在本机跑、数据不出机器**的测试辅助平台。
> 把测试日常里散落在书签、Excel、微信、Apifox、本地文件夹的东西收进一处：
> 账号密码、接口记录、SQL 片段、用例索引、压测脚本、知识库、笔记，
> 再加上代码生成 / 调试 / 体检 / 报告分析。

**适合**：手工测试、接口测试、自动化测试、性能测试的同学，一个人用。
**不适合**：需要多人协作、权限管理、云端同步的场景——它就是单人本地工具。

| 项 | 值 |
|---|---|
| 当前版本 | **v0.61.0** |
| 测试基线 | **64 个套件 / 5087 项**（unit 60 + env 4） |
| 运行环境 | Windows 10/11（x64），安装包约 120 MB |
| 数据位置 | `%APPDATA%\测试工作台\` |

**三条不动的边界**（选它的理由）：

1. **纯本地离线**——唯一的联网点是「检查更新」，由你点按钮触发，不会偷偷连；
2. **零大模型依赖**——所有能力都是规则和模板，没有 AI 调用；
3. **绝不连公司测试库**——不装任何数据库驱动，SQL 只生成不执行。

## 一、5 分钟上手

### 1. 装

下载 `test-tool-Setup-x.y.z-x64.exe`，双击安装。

> 装到 `Program Files` 需要管理员权限，会弹 UAC。

### 2. 配目录

打开后 **设置 → 目录配置**。只填一个「工作区」也行，下面几项会自动推导：

| 设置项 | 放什么 | 例子 |
|---|---|---|
| **工作区** | 上面所有目录的父目录（推荐只配这一个） | `D:\我的工作区` |
| **测试用例** | markdown 用例 | `D:\我的工作区\test_cases` |
| **压测（JMeter）** | `.jmx` 脚本 + JMeter 路径 + 压测报告 + Allure 报告 | `D:\我的工作区\jmx` |
| **知识库** | 业务规则 markdown | `D:\我的工作区\知识库` |
| **测试笔记** | 日常 markdown | `D:\我的工作区\notes` |
| **代码项目** | 你的自动化工程根目录 | `D:\Project\OTA-automation` |

> **注意**：不配也能用，只是「用例 / 压测脚本 / 知识库 / 笔记」四个页面会是空的。
> 平台不会往里写文件（唯一的例外见 [压测脚本的局部编辑](#压测脚本)）。

### 3. 示例数据（可选）

**全新空库首次启动会写入 11 条示例**，每个功能页 1-2 条，都带「示例」标签：

| 模块 | 示例 |
|---|---|
| 网站管理 | 「示例商城-管理后台」（2 个账号）+「示例商城-运营端」 |
| SQL 片段 | 按订单号查订单（带变量）+ 清理过期日志 |
| 接口记录 | 登录 / 查订单 / 创建退款（含 headers、body、响应示例） |
| 测试执行 | 1 条接口测试 + 1 条压测（带完整指标） |
| 页面元素 | 登录页（4 个元素）+ 订单列表页（3 个元素） |

还内置一个**迷你示例项目**和一份**迷你 allure 报告**（`%APPDATA%\测试工作台\demo\`），
代码体检和报告分析可以直接拿它试手。

> **不要示例**：设置 → 数据与备份 → **清除示例**（只删带「示例」标签的记录 + demo 目录）。
> 清过之后不会再写入（用 `meta.demoSeeded` 记着）。
> 老版本升级上来不会补示例——免得你的 50 条数据里混进 11 条假的。

### 4. 录第一条数据

**网站管理 → 新增** → 填名称、地址、环境 → **添加账号** → 填账号密码 → 保存。

点列表里的 🌐 图标：**浏览器打开 + 密码自动进剪贴板**，切过去 Ctrl+V 就能登录。

## 二、功能地图

侧边栏按工作流分四组，共 19 个入口：

```
资产      网站管理 / SQL 片段 / 接口记录 / 测试执行 / 页面元素 / 流程模板   ← 存
索引      测试用例 / 压测脚本 / 知识库 / 测试笔记                        ← 读（只读）
自动化    代码生成 / 代码调试 / 代码体检 / 脚本生成 / 报告分析            ← 写 / 跑 / 查
辅助      测试数据 / JSON 工具 / 工具箱                                  ← 小工具
```

| 入口 | 一句话 | 你的文件会被改吗 |
|---|---|---|
| **网站管理** | 一个站点挂多个账号，一键打开 + 复制密码 | 否（存在平台的数据库里） |
| **页面元素** | 表格化维护定位器，**点 ▶ 用你自己的浏览器实时点验**，一键生成 Page Object | 否 |
| **接口记录** | 从 Apifox 导出文件导入 / 粘 cURL / 手敲 | 否 |
| **测试执行** | 接口测试 / UI 测试 / 压测，跑一次记一笔 | 否 |
| **SQL 片段** | 存 SQL 模板，变量填完复制 | 否 |
| **流程模板** | 接口积木拼的流程存成模板，下次载入 | 否 |
| **测试用例** | 索引 markdown 用例 | **只读** |
| **压测脚本** | 解析 jmx，看线程组 / 采样器 / 断言；**可局部改数值写回** | **仅局部编辑会写**，且先备份 |
| **知识库** | 索引业务规则文档 | **只读** |
| **测试笔记** | 索引笔记，支持从桌面导入 | **只读**（导入会移动文件，你主动点才会） |
| **代码生成** | 接口 / JSON / 建表语句 / 页面元素 → 代码骨架 | 否（保存是你选目录） |
| **代码调试** | 在平台里跑 Groovy / Python / pytest / Maven | 否 |
| **代码体检** | 覆盖矩阵 + 硬编码 / 脆弱定位 / 断言质量 / 依赖冲突 | **只读** |
| **脚本生成** | 生成 `.jmx`；生成 MySQL / SQLite 快照清理 SQL | 否（SQL 只生成不执行） |
| **报告分析** | Allure 失败聚类 / Flaky / 归档到账本 / 失败用例定位源码 | 否 |
| **测试数据** | 手机号 / 身份证 / 多字段 CSV 批量生成 | 否 |
| **JSON 工具** | 格式化 / 压缩 / 转义 / 校验 | 否 |
| **工具箱** | Base64 / 时间戳 / 哈希 / UUID | 否 |

> 平台里所有代码块都带**行号 + 语法高亮**（java / python / json / xml / sql / bash / groovy 自动识别），
> 行号不参与复制——复制出去的就是纯代码。

## 三、资产库：存你自己的东西

### 网站管理

一个站点下挂多个账号，每个账号带用途和角色。

**怎么用**

1. **新增** → 填名称、地址、环境
2. **添加账号** → 填用途（管理员/商家）、账号、密码、角色
3. 勾一个「设为默认」——一键启动时用它
4. 保存 → 点列表里的 🌐

**🌐 的行为**

| 情况 | 行为 |
|---|---|
| 有默认账号 | 打开 URL + 复制默认账号密码 |
| 只有一个账号 | 用它 |
| 多个账号没设默认 | 弹窗让你选 |
| 没账号 | 只打开 URL |

**注意**

> - 密码用 Windows DPAPI 加密，库里是 `enc:` 开头的密文。
> - **搜索搜不到密码**（后端 SQL 和前端过滤两层都排除了密码字段）。
> - **换机器 / 换 Windows 账户后密码解不开是正常的**（DPAPI 绑本机）。
>   v0.51 起：解不开的字段不再显示成空，而是提示「本机无法解密，留空保持不变」，
>   **你直接保存也不会把原密文覆盖掉**；只有输入新密码才会覆盖。
> - 「导出含密码」会导出明文，只在自己机器间搬运用，**别外发**。

### 页面元素

Playwright 定位器台账——表格里一行一个元素，生成 POM 时直接取。

**怎么用**

1. **页面元素 → 新增** → 填页面名、所属项目
2. **页面地址**要填**带协议的完整地址**（`https://www.example.com/login`）——
   只填 `/login` 这种相对路径不行，实时校验要拿它当起始地址起浏览器
3. 表格里逐行填：名称 / 定位方式 / 定位值 / 说明
4. 到「代码生成」选 **Playwright POM** → 从已有页面载入 → 生成

**9 种定位方式**：CSS、XPath、Role、Label、Placeholder、Text、AltText、Title、TestId。

**项目词表**：`新增` 旁的 `⋯ → 管理项目…`，小窗里增删改只影响「所属项目」这一套（v0.55 从设置页搬过来）。

**注意**

> - 选 Role 时要填 ARIA 角色（button / textbox / link…），生成出来是
>   `getByRole(AriaRole.BUTTON, ...)` 或 `get_by_role("button", ...)`。
> - 这一页是**你自己维护的台账**，平台不会去你代码里反查——改了代码记得回来改这里，
>   否则生成的 POM 和实际界面会对不上。

#### 实时校验（点一下，框给你看）

录完元素想知道它到底抓不抓得到？不用开 DevTools 一个个试。

**怎么用**

1. 页面元素编辑器里，某一行的右端点 **▶ 校验**（**查看详情页**的元素行末尾也有一个，只读、不用进编辑）
2. 平台用**你本机的 Edge**（没装就用 Chrome）打开这条记录的 `url`
3. 页面上的目标元素被框出来（会滚动到可见位置）
4. 你在浏览器里**自己点它、看请求、看跳转、看弹窗** —— 平台不替你做判断
5. 想再来一次：**重新高亮** / **重新打开页面**；验完 **关闭浏览器**

一个页面十几个元素时，用顶栏的 **▶ 按顺序校验**：从第一行开始逐个高亮，
面板显示「第 3 / 12 个」，四个按钮是 **下一个 / 重复当前 / 跳过 / 停止**。

**平台只会告诉你事实，不会说“对/错”**

| 面板显示 | 含义 |
|---|---|
| 已在页面上高亮：`loginBtn` | 找到唯一一个，框住了 |
| 匹配到 3 个，框的是第 1 个 | 定位器太宽 —— 这条本身就是有用的信息 |
| 当前没找到这个元素 | 定位器没命中 |
| 元素当前不可见（虚线红框） | 命中了但 `display:none` / 被遮住 |
| 元素在 iframe 里，这一版不高亮 | 边界，明确告诉你而不是假装成功 |
| 元素在 shadow DOM 里，这一版不高亮 | 同上 |

**面板上能做什么**

| 位置 | 作用 |
|---|---|
| **浏览器** 下拉 | 跟随系统 / Edge / Chrome（跟着本机记住；换浏览器要重新点一次校验才生效） |
| 重新高亮 | 不导航，只把框重新画一遍（页面跳走了也能用） |
| 重新打开页面 | 重新导航到记录的 url 并框住当前元素 |
| **结束校验** | **关掉浏览器进程 + 收起面板**（任何状态下都能点，不会让你没法收场） |

**注意**

> - 进「查看详情」**不会自动跑校验**——只有你真的点了 ▶ 才会启动；点空白处关掉详情会顺手把浏览器关掉。
> - 同一个会话里反复点不会开第二个窗口；每点一次都会先清理上一次留下的残留进程。
> - **进度不写进台账**：按顺序校验走到第几个只存在界面内存里，关掉面板即结束——不会在你不知道的时候改数据。
> - **第一次要在弹出的浏览器里登录一次**：用的是独立 profile（`%APPDATA%\测试工作台\sniff-profile`），之后 cookie 留着，不用反复登。
> - **浏览器只会收到“打开这个地址 + 框住这个元素”**：不读 cookie、不读 storage、不读页面内容。
> - 平台起的浏览器会在退出应用时一起关掉；你自己关掉它也行，面板会变成「会话已结束，可重新开始」。
> - 面板上的「结束校验」= 关掉浏览器进程 + 收起面板（一次性收干净）。
> - 只在**安装版**里可用：浏览器预览模式（`build -- --preview`）没有这套能力，会直接说明。

#### 用 Playwright codegen 录制（录入交给它，平台负责入库）

如果你更习惯用 Playwright 自带的录制器，那条路径也接好了。

**怎么用**

1. 页面元素编辑器顶栏点 **🎬 用 codegen 录制**
2. 点「启动录制器」→ 平台用**「设置 → 开发环境」里配的那个 Python** 执行
   `python -m playwright codegen <记录的 url>`
3. 在录制器窗口里正常操作页面，它会实时生成定位器代码
4. 点录制器里的 **Copy**，把代码粘回平台的小窗 → **识别并添加**

**它只认定位器**：`get_by_role / get_by_test_id / get_by_label / …` 会被解析成台账行，
`click / fill / press` 这类动作忽略；同一行重复粘贴会去重。

**注意**

> - **不用选语言**：平台会自己挑一个能用的录制器（Python 录制器 → 本机 Maven 缓存里的 jar → 你的项目 → Node 版），
>   粘贴回来的代码 Python / Java / JS 三种写法都认。Inspector 右上角的 **Target** 还能随时切输出语言。
> - **录制器会直接用你系统里的 Chrome / Edge**（`--channel`），所以**不会**因为你装的 Playwright 版本和
>   浏览器内核版本对不上而打不开——那种情况下老版本会报 `Executable doesn't exist at ...chromium-XXXX`。
>   万一还是失败：平台给 3 秒宽限期，秒退就把退出码 + 日志尾部贴回界面（完整日志在 `%APPDATA%\测试工作台\codegen.log`），
>   按提示跑一次 `python -m playwright install chromium` 也能补上。
> - **想原生录 Java**：不需要你的项目——平台会直接跑本机 Maven 缓存里那套 Playwright jar
>   （`~/.m2/.../com/microsoft/playwright/{playwright,driver,driver-bundle}-<ver>.jar`）；
>   缓存里没有时才退到「你的 Maven 项目」→「Node 版」。
> - 中文文本会先落成 `el1 / el2` 这种占位名（生成的 POM 要合法标识符），你按需改成 `loginBtn` 这类名字。
> - 录制器和「实时校验」是两条独立的路：前者用来**录入**，后者用来**点验**；两者共用同一个「浏览器」偏好。

### 接口记录

三种录入方式：

| 方式 | 操作 | 说明 |
|---|---|---|
| **从 Apifox 同步** | 新增 ▼ →「从 Apifox 同步」→ 选 `openapi.json` | 幂等 upsert，会算变更 diff |
| **粘 cURL** | 新增 ▼ →「粘贴 cURL 导入」 | Chrome / Postman / Apifox 复制出来的命令都能认 |
| **手动新增** | 新增 ▼ →「手动新增」 | 一条条敲 |

**注意**

> - **按钮叫「同步」，实际是「导入导出文件」**：Apifox 那边要你手动导出 `openapi.json`（或 yaml），
>   平台只读文件、不联网、不调 Apifox 接口。所以文件不新，镜像就不新。
> - **模块词表在「新增」旁的 `⋯` 里维护**：`⋯ → 管理模块…` 打开一个小窗，增删改都只影响模块这一套
>   （原来在设置页，v0.55 搬到这里，贴着用到它的地方）。
> - Swagger 2.0 会被拒并提示「请重新导出为 OpenAPI 3」。
> - `headers` / `body` 支持「表格 / JSON」两种视图切换，超 5 行自动折叠。
> - 重复导入同一份文件是安全的：接口不会翻倍，只会更新变化了的字段并列出变更。

### 测试执行（账本）

接口测试、**UI 测试**、压测，三类都记在这里。

**怎么用**

- 手动记：**测试执行 → 新增** → 选类型（接口测试 / UI 测试 / 压测）→ 字段会跟着类型变
- 压测：**导入压测报告** → 选 `result.jtl`（或 `statistics.json`）→ 自动填并发 / TPS / P90 / P95 / P99 / 错误率 / 样本数
- Allure：在「报告分析」页点「归档到执行记录」，类型可选接口测试或 UI 测试
- 代码调试：跑完点「记入执行账本」，退出码 / 耗时 / 失败数自动预填

**注意**

> - 「通过 / 失败数」只有接口测试和 UI 测试有；压测换成并发 / TPS / P95 那一套指标。
> - 关联了报告目录的记录，详情里能一键跳回「报告分析」重新打开那份报告。
>   压测导入的记录不给这个入口（jmeter 报告目录，报告分析页解析不了）。
> - 账本是**手工 + 半自动**的：平台不会去监听你的 CI 或测试进程。

### SQL 片段

存模板，变量填完复制。

```
select * from t_order
where order_no = {{orderNo}} and create_time > {{today}}
```

**怎么用**：新增 → 写 SQL → 在「变量说明」表里登记变量 → 列表里点复制 → 弹窗填值 →
拼接预览里变量标色（未填红 / 已填绿）→ 复制到 Navicat。

### 流程模板

接口积木拼出来的流程（调接口 → 提取变量 → 断言 → 设置变量）可以存成模板，
下次在「代码生成 → 接口积木」里载入继续改或直接生成代码。

**积木清单**（代码生成 → 动作拼装）

| 分类 | 工具侧 | 内容 |
|---|---|---|
| 导航 | — | 打开地址 |
| 断言 | — | 可见 / 隐藏 / 文本 / 包含文本 / 数量 / 属性 / 标题 / 可用 / 禁用 / 地址 / 输入值 |
| 鼠标 | — | 点击 / 双击 / 悬停 / 勾选 |
| 键盘 | — | 输入文本 / 按键 |
| 表单 | — | 下拉选择 / 上传文件 / 清空输入框 / 取消勾选 |
| 等待 | — | 等待可见 / 等待隐藏 / 等待地址 / 固定等待 |
| **工具** | — | **刷新页面 / 定时刷新 / 截图 / 调试暂停 / 滚动到元素 / 清空 Cookie / 退出并清空浏览器** |

> 「工具」这一类是 v0.59 加的：它们是**手写频率最高、又最容易写错**的那几段。
> 比如「定时刷新」会生成 `for (int i = 0; i < 3; i++) { waitForTimeout(2000); reload(); }`（Java）
> 或 `for _ in range(3):` + 两行缩进（Python），不用自己数缩进。

**积木拼完怎么拿走**：右边生成结果底部有三个按钮——

| 按钮 | 作用 |
|---|---|
| **保存到文件** | 选一个目录，直接落盘成 `<页面名>Test.java` / `test_<页面名>.py`，**带 import，能直接编译** |
| 复制 | 粘到 IDE 里自己建文件 |
| 清空 | 清掉已拼的步骤 |

> 保存写的就是**面板里当前那段代码**（手改过也按你改的存），不是重新生成一遍。

**代码会带步骤注释**（v0.61）：每个积木生成的语句上方都有一行人话，序号和「已选步骤」对得上——

```java
@Test
public void testLogin() {
    // 1. 打开地址 /login
    page.navigate("/login");
    // 2. 在 usernameInput 输入「admin」
    page.locator("#username").fill("admin");
    // 3. 固定等待：3000 ms
    page.waitForTimeout(3000);
}
```

Python 用 `#`。注释标题来自 `shared/uiActions.js` 的 `UI_SUMMARY_TEMPLATES`，新加动作忘了配就退回动作名。

**毫秒参数会自动换算**：填 `3000` 时输入框右边显示 `= 3 秒`（`2500` → `= 2.5 秒`），不用自己心算。

接口侧 10 个动作：调用接口 / 提取变量（JSONPath / 正则 / **响应头**）/ 断言状态码 /
断言 JSON 字段 / 断言响应时间 / **断言响应体包含** / **断言响应头** / 设置变量。

## 四、只读索引：平台不动你的文件

这四个页面的共同点：**平台只读你的文件，不写、不改、不移动**（笔记导入是个例外，见下）。

### 测试用例

索引 markdown 用例，两种格式都认：

```markdown
#### [高] [功能] 优惠券核销成功
前置条件：...
步骤：...
预期：...
```

```markdown
## C1 下单-支付-发货 [冒烟]
```

**注意**

> - 用例文件里的**勾选框状态不会被平台修改**。
> - 用例可以关联到「接口记录」，关联的软键是 `文件路径 + 用例标题`——
>   **改了用例标题，原来的关联会断**，需要重新关联。

### 压测脚本

解析 `.jmx`：线程组（线程数 / Ramp / 循环 / 持续）、采样器、断言、CSV 数据源、HTTP 头，
外加一轮**健康检查**（比如 CSV 文件不存在会标红）。

#### 局部编辑（会写回文件）

这是平台**唯一会改你资产**的功能，所以限制得很死：

**怎么用**

1. 列表里点开一个 jmx → 详情抽屉滑到底
2. 点「展开编辑」（默认是折叠的，只读优先）
3. 改「线程组」或「断言」里的数值 → 改过的行会标黄点
4. 点「保存并写回」→ 确认框会逐条列出 `10 → 20` 这样的变化
5. 确认 → 写入，提示里带上备份文件名

**能改什么**（白名单，别的字段一律拒绝）

| 类型 | 字段 | 合法值 |
|---|---|---|
| 线程组 / 前置 / 后置 | 线程数 | 1 – 1000000 |
| 同上 | 爬坡秒 | **0** – 1000000（0 = 立刻全部启动） |
| 同上 | 循环次数 | **-1（永久循环）** 或 1 – 1000000 |
| 响应断言 | 期望值 | 长度 ≤ 500，不能含 `<` `>` |

**注意**

> - **写前必备份**：同目录生成 `xxx.jmx.bak-20261125-165114`，内容等于原始字节。
>   保留份数跟「每日备份」共用同一个设置（默认 10 份），见 [备份](#八数据备份与隐私)。
> - **只改值的几个字节**：实测 47 KB 的计划改一个线程数，全文只有 `10`→`77` 两个字符变化，
>   缩进、换行、属性顺序都不动。
> - **文件被别人改了会拒绝写**：详情打开后如果 jmx 被 JMeter 另存或被同事改过，
>   保存会提示「文件已被外部改动，请重新加载详情」，这一次什么都不写。
> - **扫描不认 CDATA 里的假标签**：极端情况下（JSR223 脚本里以 CDATA 内嵌 `<ThreadGroup`）
>   会导致线程组编号偏移，偏移后通常回「找不到目标」而不是改错地方。
> - 改完左侧列表会就地更新；如果没更新，点「重新扫描」。

### 知识库 / 测试笔记

索引 markdown，目录树 + 搜索，默认只显示第一节，可「阅读全文」。

**注意**

> - **「导入」是移动语义**：从桌面导入的笔记会被搬到笔记目录，原文件消失。
>   这是你主动点的动作，不是平台偷偷干的。

## 五、生成：写代码之前

### 代码生成

**6 种生成目标**

| 目标 | 从什么生成 |
|---|---|
| Java · REST Assured | 接口记录 / OpenAPI 文件（TestNG + REST Assured 骨架） |
| Python · pytest | 同上（pytest + requests） |
| Java · Playwright POM | 页面元素（Page Object） |
| Python · Playwright POM | 同上 |
| Java · POJO | JSON **或** 建表语句（Lombok 风格） |
| Python · Pydantic | 同上 |

**怎么用**

1. 侧边栏 **代码生成** → 选目标
2. 左侧选数据源（接口记录 / OpenAPI 文件 / JSON / 建表语句 / 页面元素）
3. **生成预览** → 右侧看代码
4. **保存到文件** → 选目录；或直接复制到剪贴板

**生成出来长什么样**（Java REST Assured，节选）：

```java
public class PetApiTest {
    @Test
    public void testCreatePet() {
        Response response = given()
            .contentType("application/x-www-form-urlencoded")
            .formParam("name", "Hello Kitty")
            .formParam("status", "sold")
        .when()
            .post("/pet")
        .then()
            .statusCode(200)
            .extract().response();

        // TODO: 补充业务断言
    }
}
```

**注意**

> - **OpenAPI 文件模式不写数据库**：别人给你一份接口文档、你只想生成几个测试类，用这个最干净。
> - 生成的代码是**骨架**，断言位置留了 `// TODO: 补充业务断言`——别直接当测试用例跑。
> - 从建表语句生成时，类型映射（bigint→Long、decimal→BigDecimal、datetime→LocalDateTime、bit→Boolean）
>   和类名（`t_order` → `Order`）都是按命名约定推的，遇到奇怪命名自己改一下。
> - 「保存到文件」只写你选的目录，**同名文件会被直接覆盖、不弹确认**——保存前瞄一眼目标目录。
>   （文件名叫什么由生成目标决定：类名 + 扩展名。）

### 断言模板库（18 个）

代码生成页右上角的「脚本模板」入口，按分类浏览、填变量、一键复制。

| 分类 | 内容 |
|---|---|
| 接口断言 | REST Assured：状态码 / JSON 字段 / JSON Schema；pytest：JSON 字段 / JSON Schema |
| UI 断言 | Playwright：元素可见 / 文本包含 / 属性值 |
| 提取器 | JSON 提取、正则提取、边界提取 |
| JMeter 断言 | JSR223：状态码 / 关键字 / JSON / 响应时间 |
| 生成 / 加密 / 流程 | UUID、时间戳、AES、If 控制器等 |

> 每个模板都带「什么时候用 / 怎么加 / 有什么坑」三段说明。

### 脚本生成 · JMeter

**怎么用**

1. 侧边栏 **脚本生成** → 「JMeter 脚本」Tab
2. 选一个或多个接口（按选择顺序执行）
3. 配线程组：线程数 / Ramp-Up / 循环次数 **或** 持续时长（二选一）
4. **生成预览** → **保存为 .jmx**

**生成的内容**：测试计划（预置 `host` / `port` 变量）、线程组、HTTP 采样器、
信息头管理器（从接口记录的 Headers 提）、响应断言（200）、持续时间断言。

**注意**

> - 域名端口用 JMeter 属性占位：`${__P(host,127.0.0.1)}`。
>   换环境不用改文件，命令行 `jmeter -Jhost=test2.com` 就行。
> - **保存为 .jmx 时同名会直接覆盖，不弹确认**——选目录时别选到你真实的脚本目录，
>   除非你确实要覆盖它（改已有的脚本请走「压测脚本 → 局部编辑」，那里会先备份）。
> - **JMeter 版本自动对齐**：从设置里配的 JMeter 路径读出版本号写进 jmx，
>   用你自己的 JMeter 打开不会弹「版本不一致」。
> - 勾「启用 CSV 参数化」时，CSV 路径是**相对 jmx 所在目录**的，和「测试数据」页导出的多字段 CSV 正好配套。
> - 生成完的 jmx 能被平台自己的解析器解析——保存后到「压测脚本」页就能看到，健康检查也是绿的。

### 脚本生成 · 数据库 SQL（MySQL / SQLite）

**核心原则：只生成 SQL，不连数据库、不执行、不存密码。**

复制到 Navicat / DBeaver / DB Browser / 命令行去执行。

**三种操作**

| 操作 | 生成什么 | 典型用法 |
|---|---|---|
| **快照** | `CREATE TABLE bak_xxx ...` + `INSERT ... SELECT` | 压测前备份数据 |
| **清理** | `DELETE`（带条件）/ `TRUNCATE` / `DROP` | 跑完清脏数据 |
| **还原** | 清空 + 从备份表灌回 | 测完恢复现场 |

**两种方言的差异，平台会自动切**

| 操作 | MySQL | SQLite |
|---|---|---|
| 建备份表 | `CREATE TABLE bak LIKE src`（含索引） | `CREATE TABLE bak AS SELECT * FROM src`（只数据） |
| 清空 | `TRUNCATE TABLE x` | `DELETE FROM x` |
| 重置自增 | `ALTER TABLE x AUTO_INCREMENT = 1` | `DELETE FROM sqlite_sequence WHERE name='x'` |
| 外键开关 | `SET FOREIGN_KEY_CHECKS = 0` | `PRAGMA foreign_keys = OFF` |
| 标识符引号 | `` `name` `` | `"name"` |
| 空间回收 | 不需要 | `VACUUM`（DELETE 后文件不会自己变小） |

**安全设计**

- `TRUNCATE` / `DROP` **默认被拒**，必须勾「我确认这是测试库」才生成
- 无条件 `DELETE` 等同于清空，同样要勾
- 表名 / 库名只允许字母数字下划线，防注入
- 生成的 SQL 顶部有 ⚠️ 警告注释

## 六、执行与检查

### 代码调试

**4 种运行器**

| 运行器 | 跑什么 | 等价命令 |
|---|---|---|
| Groovy（JMeter） | JMeter 的 JSR223 脚本 | `java -cp {jmeter}/lib/* groovy.ui.GroovyMain x.groovy` |
| Python | 独立脚本 | `python x.py` |
| Python（pytest） | pytest 用例 | `python -m pytest x.py -v` |
| Java（Maven） | 项目里的测试类 | `mvn test -Dtest=Xxx` |

**怎么用**：侧边栏 **代码调试** → 选运行器 → 写代码（Maven 模式选项目 + 测试类）→
**运行**（Ctrl+Enter）→ 下方看输出 → 跑完可「记入执行账本」。

**注意**

> - **Maven 只认 `JAVA_HOME`**，不认 PATH 里的 `java`。报「无效目标发行版: 17」多半是
>   `JAVA_HOME` 指着 JDK 8。平台会从项目 `pom.xml` 读 `<java.version>` 自动挑匹配的 JDK，
>   挑不到就在设置 → 开发环境里手动指定。
> - pytest 只跑**单文件**——想跑整个目录或 `-k` 过滤，直接开 IDE 更快。
> - 缺环境时不会装，只提示缺什么、去哪配。

### 代码体检

**四件事**

| 检查 | 看什么 |
|---|---|
| **接口覆盖矩阵** | 「接口记录」清单 vs 代码里的 `get("/api/x")` / `requests.post(...)` |
| **页面覆盖矩阵** | 「页面元素」清单 vs 代码里的 `page.goto("/login")` |
| **硬编码 / 脆弱写法** | 高：密码、Token；中：硬编码 URL、`Thread.sleep`、**断言过弱**；低：绝对 XPath、深层 CSS |
| **依赖冲突** | `pom.xml` / `requirements.txt`：重复声明、多版本共存、占位符未定义 |

**「断言过弱」长什么样**

```java
.then().statusCode(200);                                    // ❌ 只验状态码
.then().statusCode(200).body("code", equalTo(0));           // ✅ 有 Body 校验
```

```python
assert resp.status_code == 200                               # ❌
assert resp.status_code == 200 and resp.json()["code"] == 0  # ✅
```

**注意**

> - 实现是**启发式**（正则 + 缩进 / 大括号切块），不是 AST。
>   换句话说：它会给建议，不会给你下判决书。
> - **不做传递依赖分析**——那要解析完整依赖树还得联网。查依赖冲突请用 `mvn dependency:tree`。
> - 扫描有上限（3000 文件 / 单文件 1 MB / 500 条问题），**截断会在结果里明说**，不会假装扫全了。
> - 覆盖矩阵依赖你自己维护的「接口记录 / 页面元素」清单——清单不新，结论就不准。

### 报告分析

**失败聚类**：把错误信息里的数字 / UUID / 路径 / 引号内容替换成占位符，相同模式归一组。

```
Timeout 3000ms waiting for #btn
Timeout 5000ms waiting for #btn
  ↓ 归一化
Timeout <N>ms waiting for #btn     ← 同一组
```

**Flaky 追踪**：选 2 个以上执行记录，比对同一用例的通过 / 失败，标出不稳定的。

**失败用例 → 定位源码**

1. 失败用例行内点「定位」
2. 平台按 `testClass` 在「代码项目目录」里找源文件
3. 找到就在文件管理器里选中它，并把 `文件:行` 复制到剪贴板

**注意**

> - **只到文件，不跳行**：平台不装编辑器插件（底线），
>   行号是从 Allure 失败堆栈里取的真实值，复制成 `XxxTest.java:42` 粘到 IDE 的跳转框就能到行。
> - 找不到类就返回空列表，**不会猜一个最像的**——猜出来的定位点比没有更坑。
> - 同名不同包时会让你选。
> - 报告的归档可以选类型（接口测试 / UI 测试），选错了账本口径就乱了。
> - 报告目录要先在 **设置 → 目录配置 → 压测（JMeter）** 里配「Allure 报告目录」，或者每次手动「选目录」。

## 八、数据、备份与隐私

### 数据位置

| 内容 | 位置 |
|---|---|
| **数据库**（账号 / 接口 / SQL / 执行记录 / 页面元素 / 流程模板） | `%APPDATA%\测试工作台\data.db` |
| **备份** | `%APPDATA%\测试工作台\backups\` |
| **示例项目 / 示例报告** | `%APPDATA%\测试工作台\demo\` |
| **你的文件**（用例 / jmx / 知识库 / 笔记） | 你自己配的目录，**平台不复制** |

### 备份

**两类备份，共用一个保留份数**

| 谁产生 | 落在哪 | 什么时候 |
|---|---|---|
| 每日自动备份 | `%APPDATA%\测试工作台\backups\data-YYYY-MM-DD-*.db` | **当天第一次启动**时（一天只做一次） |
| jmx 写回备份 | jmx 文件**同目录** `xxx.jmx.bak-<时间戳>` | 每次局部编辑写回 |

**保留份数在设置 → 数据与备份里改一个数，两处同时生效**（默认 10，范围 1..100）。

> - 填 0 或乱填会**回落成 10**，不会变成「一份都不留」。
> - 另外两类副本**不参与轮转、一份都不会自动删**：
>   迁移前（`data-before-v*.db`）、恢复前（`data-before-restore-*.db`）。出事了要靠它们救。
> - 同一秒内连点「立即备份」会生成同名文件互相覆盖——**不会丢数据**，只是少留一份。

**导出怎么选**

| 按钮 | 导出什么 | 用在哪 |
|---|---|---|
| **导出整库** | 整个 `data.db` | 换机器首选：含所有集合 + 关联 + 选项 |
| **导出** | 所有集合的 JSON（**不含密码**） | 分享 / 提交到仓库 |
| **导出含密码** | JSON + **明文密码** | 只在自己机器间搬，**别外发** |

> 集合页的「导出」只导当前集合，同样不含密码。

### 恢复

设置 → 数据与备份 → 选备份 → 恢复。

> - 恢复前自动留一份 `data-before-restore-*.db`。
> - **恢复失败时原库一个字节都不会动**（v0.51 修的），会明确告诉你失败原因。
> - 比当前程序更新的备份会被拒绝（先升级程序再恢复）。

### 搬家（换电脑）

1. 旧机器：设置 → 数据与备份 → **导出整库** → 得到一个 `.db`
2. 新机器：装好 → **恢复** → 选那个 `.db`
3. 新机器：把用例 / jmx / 知识库 / 笔记目录指到对应位置

> **旧备份能用**：恢复时自动跑数据迁移（v1 → v7）。
> **但密码解不开**：DPAPI 绑本机，换机器后密码字段会提示无法解密，需要重新录入。
> 这是 Windows 的机制，不是 bug。

### 隐私边界

| 问题 | 答案 |
|---|---|
| 会联网吗 | 只有「检查更新」会，点按钮才触发，可以永远不点 |
| 会连数据库吗 | 不会，没装任何数据库驱动；SQL 只生成不执行 |
| 会上传数据吗 | 不会，没有服务端、没有账号体系 |
| 会调大模型吗 | 不会，全部规则和模板 |
| 锁屏 PIN 防什么 | 防**路过的人瞄屏幕**，不防会操作你电脑的人（4 位 PIN 可穷举） |

## 九、设置速查

设置页按 6 类整合，顶部有快速导航：

## 十、环境要求

**平台只检测，不下载、不安装**——不改你的系统环境，卸载时也不会删它们。

| 环境 | 版本 | 用在哪 | 缺了怎么办 |
|---|---|---|---|
| JDK | 17+ | 代码调试（Maven）、代码生成 | 自己装，或在设置里指定 |
| Python | 3.10+ | 代码调试（Python / pytest） | 同上 |
| Maven | 3.8+ | 代码调试（Maven） | 同上 |
| JMeter | 5.x | 代码调试（Groovy）、压测脚本、脚本生成 | 设置 → 压测里配路径 |
| Playwright 浏览器 | — | 跑 Playwright 测试 | `npx playwright install` 或 `mvn playwright:install` |

> - 设置 → 开发环境能看到每项的检测结果（✓/✗ + 路径 + 版本）。
> - 多版本共存没问题：平台会列出所有已装的 JDK / Python，按项目需要自动挑，也能手动指定。
> - Java 和 Python 的 Playwright **共用同一个浏览器缓存**（`%LOCALAPPDATA%\ms-playwright`），只下一份。

## 十一、常见问题

### Q：卸载时勾「删除用户数据」，会删掉我的 JDK / Python 吗？

不会。只删 `%APPDATA%\测试工作台`（数据库、备份）和平台在「文档\测试工作台」里建过的目录。
JDK / Python / Maven / JMeter / Playwright 浏览器都是你自己装的，不会被碰。

### Q：平台会改我的 markdown / jmx 文件吗？

- 用例 / 知识库 / 笔记：**只读**。
- jmx：默认只读；只有你主动「展开编辑 → 确认写回」才会改，而且**只改白名单字段的那几个字节**，写前先备份。
- 笔记的「导入」会把文件搬到笔记目录（移动语义），这是你点的。

### Q：更新版本会丢数据吗？

不会。数据在 `%APPDATA%`，安装包只覆盖程序文件。
改了数据结构时会自动迁移，迁移前先备份（`data-before-vN-*.db`）。

### Q：密码解不开了 / 打开一看密码是空的？

**没坏，是设计。** 密码用 Windows DPAPI 加密，绑本机和当前 Windows 账户。
换机器、换账户、重装系统后就解不开了。

v0.51 起的行为：解不开的字段不显示成空串，而是提示「本机无法解密，留空保持不变」，
**你改别的字段再保存，也不会把原密文覆盖掉**。想恢复只能重新输入一次密码。

### Q：局部编辑提示「文件已被外部改动」？

说明你打开详情之后，这个 jmx 被 JMeter 另存过、或被别的程序改过（mtime / 大小变了）。
点「重新加载详情」再改一次即可——**这一次什么都没写**，不会覆盖别人的改动。

### Q：改了线程数，左侧列表还是旧值？

正常情况下写回成功会就地更新那一行。没更新就点「重新扫描」。

### Q：Maven 跑测试报「无效目标发行版: 17」？

`JAVA_HOME` 指着 JDK 8，但项目要 17。**Maven 只认 `JAVA_HOME`，不认 PATH 里的 `java`。**
平台会从 `pom.xml` 读 `<java.version>` 自动挑匹配的 JDK；还不行就在设置 → 开发环境里手动指定。

### Q：代码调试提示「缺少环境：JMeter」？

设置 → 目录配置 → 压测（JMeter），配上 `jmeter.bat` 的路径。

### Q：报告分析找不到 allure-results？

点「选目录」手动指定；或确认项目跑过 `mvn test` 且配了 Allure 插件，报告落在 `target/allure-results`。

### Q：安装时提示「程序正在运行」，但我关了？

它缩在托盘里。右下角托盘区（可能要展开 `^`）→ 右键平台图标 → 退出。
不想每次都这样：设置 → 行为与安全 → 点 X 时选「退出程序」。

### Q：我不想要示例数据？

设置 → 数据与备份 → **清除示例**。只删带「示例」标签的记录 + demo 目录，你自己的数据不受影响。

### Q：为什么老版本升级上来没有示例数据？

示例只在**全新空库首次启动**时写入。已有记录的库会跳过——免得你的数据里混进假数据。

### Q：数据能同步到别的机器吗？

不能自动同步（没有云端）。用「导出整库 → 恢复」手动搬。

### Q：点「▶ 校验」提示「没找到浏览器」？

平台需要本机的 Microsoft Edge 或 Google Chrome（先找 Edge，没有再找 Chrome）。
两个都没装的话就没法起浏览器——装上任意一个即可，不需要额外装 Playwright。

### Q：元素明明在页面上，校验却说「没找到」？

三种常见原因，按顺序排查：

1. **页面还没渲染完**——等页面加载完再点一次「重新高亮」
2. **元素在 iframe 里**——面板会写「元素在 iframe 里，这一版不高亮」；跨源 iframe 里甚至只能报「没找到」
3. **定位器本身不准**——这正是这个功能要帮你发现的

反过来，如果显示「匹配到 3 个」，说明定位器太宽，跑脚本时可能点到别的元素上。

### Q：校验会改我的台账吗？

**不会。** 按顺序校验走到第几个只存在界面内存里，关掉面板就没了；全程不调保存。
要写进台账只有你自己点「保存」。

### Q：校验开了浏览器但说「刚拉起来就退出了」？

v0.56 修的就是这个：以前平台用「启动的进程是否还活着」判断浏览器就绪，
而 Windows 上 Edge/Chrome 启动时可能只是转发一下命令就退出，真正的浏览器进程还在跑。
现在只看调试端口文件（`DevToolsActivePort`），进程退出只记日志。

如果**仍然**遇到，通常是上一次的浏览器卡在配置目录里：面板上点「结束校验」收干净，再点一次校验即可。

### Q：为什么它拉起的是 Edge，我默认浏览器是 Chrome？

「跟随系统」读的是 Windows 注册表里的 URL 关联（`...\UrlAssociations\http\UserChoice`）。
如果你的 Chrome 没有真正把关联写进注册表，系统默认看起来是 Chrome、但这台机器的 UserChoice 却是 Edge。

在面板的「浏览器」下拉里**显式选 Chrome** 就行——选择会记住，之后都按你选的来。

### Q：备份到底留几份？在哪改？

设置 → 数据与备份 → 「保留最近 [ ] 份」。**一个数管两处**：每日自动备份 + jmx 写回的同目录 `.bak`。
### Q：数据库坏了会怎样？

启动时会做完整性检查，坏了会**自动回落到最近的可用备份**并弹窗告诉你，坏文件改名留在 `backups\data-corrupt-*.db`。
如果一份可用备份都没有，会明确报错并告诉你原文件在哪——不会假装正常启动。

## 十二、已知限制

| 限制 | 说明 |
|---|---|
| **单人本地** | 没有多用户 / 权限 / 审计 |
| **无云端同步** | 换机器手动导出导入 |
| **markdown 只读** | 不在平台里编辑用例 / 知识库 / 笔记（用 Typora / VSCode） |
| **jmx 只改 4 类字段** | 线程数 / 爬坡 / 循环 / 断言期望值；改结构请用 JMeter GUI |
| **前置 / 后置线程组** | 能看能改数值；但若同一个文件里用 CDATA 内嵌了假标签，编号可能偏移（会拒绝而不是改错） |
| **定位源码不跳行** | 只到文件 + 复制 `文件:行`，不装编辑器插件 |
| **实时校验不跨 iframe / shadow DOM** | 这两类里的元素不高亮，面板会明说；跨源 iframe 更只能报「没找到」 |
| **代码体检是启发式** | 正则切块，不是 AST，会给建议不下判决 |
| **不下载环境** | JDK / Python / Maven / JMeter / 浏览器要自己装 |
| **无 AI** | 全部规则 / 模板驱动 |

### 常用命令

```powershell
cd Project\test-tool

npm install
node scripts/build.mjs        # 生产构建
node scripts/build.mjs -- --preview   # 预览构建（含 mock，浏览器可开）

npm test                      # unit 档 60 套件 / 4944 项（自检先跑）
npm run test:env              # env 档 4 套件 / 127 项（需设 4 个目录变量）
npm run test:all              # 全量 64 套件 / 5087 项
npm run test:gui              # 只跑 GUI 冒烟（19 路由 + 5 类交互，约 26 秒）
npm run check                 # 只跑提交前自检
npm run dist:installer        # 打 NSIS 安装包
```

**验证安装包**（打完必做，比时间戳可靠）：

```powershell
$env:ELECTRON_RUN_AS_NODE="1"
& ".\node_modules\electron\dist\electron.exe" scripts\verify-asar.cjs
# 退出码：0 = PASS / 1 = FAIL / 2 = 无法验证（缺 release\win-unpacked，别当成功）
```

### 发版流程

```powershell
# 1. 改 package.json 的 version
# 2. 过自检 + 测试
npm run check
npm test
# 3. 打安装包
npm run dist:installer
# 4. 打文档包
npm run package:docs
# 5. 验证包内内容 = 当前源码（退出码 2 = 无法验证，别当成功）
$env:ELECTRON_RUN_AS_NODE="1"
& ".\node_modules\electron\dist\electron.exe" scripts\verify-asar.cjs
# 6. 提交 + 打 tag
# 7. 上传 Release —— 三个文件缺一不可：
#      test-tool-Setup-<ver>-x64.exe   （安装包）
#      latest.yml                       （electron-builder 生成，含安装包 sha512）
#      test-tool-docs-<ver>.zip         （文档包）
#    ⚠️ 漏了 latest.yml，应用内「检查更新」能查到新版本，但下载会被完整性校验拒绝
# 8. 清理旧产物，只留最新一版（先 --dry-run 看一眼再删）
node scripts/clean-release.cjs --dry-run
node scripts/clean-release.cjs
```

### 加一个集合 / 工具

- **集合**：`shared/collections.js` 的 `COLLECTIONS` 加一项（字段定义）→ 前端自动出现
- **工具**：`TOOLS` 加一项（带 group）→ `src/pages/` 加页面 → `src/App.tsx` 加路由

### 开发注意（踩过的坑）

- **改动要按「四类场景」验收**：冒烟（还活着）/ 正向（结果对）/ 反向（非法输入被明确拒）/ 异常（环境坏了不崩）
  ——对改动点 + 可能受影响的模块做，**不必每次跑全平台**。先跑 `node scripts/affected.cjs` 看影响面。
- 新增测试必须登记 `scripts/lib/suites.cjs`，否则 `run-unit` 直接退出 1
- **不要用 PowerShell `Get-Content | Set-Content` 改仓库里的中文文件**——会按 GBK 读、把汉字和后面的换行一起吞掉
- `shared/` 里带 `require('ejs')` 的模块不能进前端（构建会失败）
- antd 受控 `value=""` 会吞 placeholder，要传 `undefined`

> 更细的开发约定、迭代记录、144 条踩坑笔记在 `docs/` 下（不进 git，随 Release 的文档包分发）。
