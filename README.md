# 测试工作台

本地测试效率工具。密码库、测试账号、SQL 片段、接口记录、测试笔记，加三个随手用的小工具。
所有数据都在本机，密码字段用 Windows DPAPI 加密，不联网、不上传。

## 功能

> 界面截图不随代码仓库分发（避免把真实路径/账号带进 git）。
> 需要看图时解压 Release 里的 zip，`docs/screens/` 下有全部截图。

| 模块 | 能做什么 |
| --- | --- |
| 网站管理 | 测试环境地址 + 环境（可多选）+ 账号密码；列表里直接点图标用默认浏览器打开、按环境筛选、一键复制密码 |
| 测试账号 | 环境（可多选、可筛选）、角色/权限（可多选）、所属站点（关联网站记录，选站点自动带出环境）、到期日 |
| SQL 片段 | SQL 里写 `{{orderNo}}` 这类占位符，复制时弹框填值再替换 |
| 接口记录 | 方法 / URL / Headers / Body，一键复制成可直接执行的 cURL；**从 Apifox 导出的 openapi.json 一键同步**（模块/描述/参数/Schema/完整度，带你自己的备注层）；**同步时做变更 diff：哪个接口改了什么 → 哪些已关联用例要重跑**；详情里「关联用例 [n]」挂上会反复测的用例（带灰字候选） |
| 测试执行 | 接口测试 / 压测跑一次记一笔：结果、场景、指标（TPS / P95 / 错误率 / 通过失败数）、结论、报告链接；可关联接口，接口详情里就直接看到「最近执行」 |
| 测试笔记 | Markdown 编写与预览，全文搜索 |
| JSON 转化 | 格式化、压缩、转义、去转义、合法性校验 |
| 测试数据 | 姓名/手机号/邮箱/身份证/银行卡/地址/公司/UUID/日期/金额/订单号，批量生成 |
| 工具箱 | Base64、URL 编解码、MD5/SHA-1/SHA-256、时间戳互转、随机密码 |
| 时间计算 | 两个时间的差值（几天几时几分几秒 + 合计秒数）；给一个基准时间 ± x 秒/分/时/天/周，推算出结果时间和时间戳 |
| 测试用例 | **只读索引**你的 markdown 用例：按目录浏览、按风险/冒烟/核心路径筛选、全文搜索（含检查项与断言迹）、详情里看前置/操作/预期/三维断言迹；一键打开源文件；详情底部看「关联接口」并一键跳过去 |
| 压测脚本 | **只读索引** jmx：解析线程组/采样器/CSV/变量/断言/集合点，做「能不能跑」的健康检查；一键用 JMeter GUI 打开编辑 |

列表页统一能力（五个集合通用）：

- 左侧**标签栏**：按标签筛选，显示每个标签的记录数；收藏（未关闭收藏的集合）
- 环境筛选 + 关键词搜索 + **排序**（最近修改 / 最早修改 / 名称 A→Z / Z→A）
- 每条记录的**导入 / 导出**（导出为 JSON，导入按集合过滤，其他集合的记录自动跳过）
- 空状态引导，列表超过 50 条自动分页

### 压测脚本（jmx 只读索引）

jmx 是 XML，平台**只解析不修改**——编辑器归 JMeter GUI。解析规格按 xdclass《玩转 Jmeter5.X》教程讲的组件来：

- **线程组**：并发数、ramp、调度器、循环次数、启用状态；区分 setUp / 普通 / tearDown
- **HTTP 采样器**：method、path、domain、port、参数
- **HTTP 请求默认值**：采样器 path 留空时继承它（教程第八章），所以不误报
- **CSV Data Set Config**：文件路径、变量名、分隔符、共享模式
- **断言**：响应断言（状态码/文本）、持续时间断言（RT 上限）、BeanShell 断言
- **其他**：用户定义变量、信息头、JSON 提取器、同步定时器（集合点）、监听器、循环控制器、`${占位符}`

健康检查（规则全部来自教程，不自己发明）：

| 检查 | 依据 | 级别 |
|---|---|---|
| 没有任何断言 | 第四章：响应断言 + 持续时间断言是常规必备 | 黄 |
| CSV 文件不存在 | 第五章：上传压测机器要改路径 | 红 |
| CSV 路径失效但同目录有同名文件 | 多半只是路径没更新 | 黄 |
| 集合点人数 > 线程数 | 第五章：不能大于线程组数量，否则一直等超时 | 红 |
| 采样器 path 空且默认值也没 domain | 真缺失 | 红 |
| 采样器 path 空但默认值有 domain | 正常复用，不报错 | 灰 |
| 占位符没有定义 | 第五章：`${XXX}` 引用 | 黄 |
| 所有线程组都禁用 | 跑起来不会有请求 | 红 |

设置 → 压测：填 jmx 目录和 jmeter.bat 路径（留空自动探测）。配好后列表里每行有「用 JMeter 编辑」，点一下 JMeter GUI 启动并加载该脚本。

### 环境 / 角色 / 标签：下拉多选 + 可配置

网站管理和测试账号的「环境」「角色 / 权限」都是**下拉多选**，选项在 **设置 → 选项配置** 里增删改：

- 环境：可以改显示名、改颜色（列表和筛选里跟着变）、新增、删除；底层 `value` 存进记录，老记录不受改名影响
- 角色 / 权限：标签形式维护，历史记录里用过的角色会自动收进来
- 标签：支持**手输 + 回车**确认，确认后自动加入标签配置，下次直接在列表里选

### 测试用例（只读索引）

用例仍然以 markdown 为准（由你自己的 agent 预设产出），工作台**只读不写**，扫描目录在设置里配（默认 `文档\测试工作台\test_cases`）。

- 识别两种格式：标准 TC（`#### [风险] [类型] 标题` + 前置/操作/预期）与极简回归链路（`## C1 标题 [冒烟]`）
- 提取风险等级、类型标签、核心路径 🛤️、覆盖规则号 `[覆盖 R…]`、三维断言迹（UI/API/DB）、检查项
- 左侧是**两层目录树**：一级 = 需求目录（如「模块B卡券」），二级 = 这个目录下的每份用例文件
  （如 `TC_模块C券_20250109.md`）。点目录看整个需求，点文件只看那一份 —— 一个需求目录里躺着好几份用例时特别有用
- 工具条按冒烟 / 核心路径 / 高风险筛选，搜索覆盖标题、前置、操作、预期、断言迹、检查项
- 详情抽屉：结构化展示用例，可一键复制成文本、一键打开源文件（或定位到文件夹）
- 解析不了的报告/评审类文件会自动排除，不会混进用例列表

### 用例 ↔ 接口关联

用例和接口是两份资产，关联是它们**之间的映射**，所以单独存一张表（`case_api_links`），既不写进 md，也不写进接口记录。

- 接口记录详情底部：「关联用例 [n]」→ 弹窗搜标题 → 多选 → 保存（再点一次取消勾选就是解除）
- 用例详情抽屉底部：「关联接口」→ 显示 method + URL，**点一下直接跳到那条接口记录**并打开
- 关联是**软键**：存「文件相对路径 + 用例标题」，每次按这两个字段回找当前用例。
  用例被改名/删掉了不会有异常，只会变成灰字「已失效」，旁边有「清理」；删接口记录时会顺手把它的关联一起清掉
- **空关联是合法状态**：没有「2865 条待关联」的待办条，没有红色警告，不关联不影响任何主流程
- **灰字候选**：弹窗顶部会按接口的「名称 / 模块 / 描述 / URL」猜几条相关用例，灰字小标签，**点了才勾上**，
  鼠标悬停能看到「命中：退款单、退款」这种依据。猜不出来就什么都不显示 —— 不塞噪音，也不算待办

为什么不做成在 md 里写接口路径：用例是先于接口产出的（开完需求会就写用例，那时路径还没定），而且一个用例可能对多个接口、历史 2865 条补不回来、路径重构时映射表只改一条。

### 接口只读镜像（从 Apifox 同步）

开发在 Apifox 建好接口、口头跟你说「XX 路径能测了」，以前你得切到 Apifox 翻目录。现在：

1. Apifox 里 **导出 → OpenAPI 3 → JSON**
2. 接口记录页右上角「**从 Apifox 同步**」→ 选文件
3. 弹一张摘要卡片：新增 / 更新 / 跳过 / 缺描述，各多少条

- **幂等**：唯一键是 `method + url`，同一个文件同步十次也只有一份记录；描述没变的那条算「跳过」，不刷更新时间
- **只覆盖 Apifox 来的字段**（名称、模块、描述、参数摘要、请求/响应 Schema、完整度）。
  你的 **「我的备注」**、标签、收藏、Headers / Body / 其他备注，同步一律不碰 —— 这是整个模块的底线
- **手写的接口会被认领**：你自己建过的占位接口（method + url 相同），同步时补上描述和 Schema，备注还在
- **URL 变了不会删老记录**：算新增一条，老的那条留着（可能是你自己改过路径，删了反而丢信息）
- **失效/缺失都不报错**：没有描述的接口标灰字「缺描述」，没写示例的标「缺示例」，都不弹警告 —— Apifox 里没写描述是常态
- 手动新增接口的入口一直留着（对应「Apifox 里找不到、先占个位」的场景），来源标「手录」

同步进来的是**快照**，不是实时数据：想更新就再导一次、再点一次同步。不做定时拉取（配置成本比收益高）、
不做平台内调试器（Apifox 有登录态，复制 cURL 过去发更省事）、不存响应体（每次写盘是整库重写，大字段会把库撑坏）。

#### 变更 diff + 影响面提醒

接口改过、用例没跟着改，是漏测最常见的原因。同步时会顺手比对一次，只挑**会让已写用例失效**的结构变化：

| 算变更 | 不算变更 |
| --- | --- |
| 必填参数增加 / 减少（含「可选变必填」） | 描述、说明文字改了 |
| 参数类型变化 | 参数顺序变了 |
| 请求体：必填字段增删、字段增删、类型变化 | Schema 里的 example / 注释改了 |
| 响应体：字段增删、类型变化 | 目录（tag）、名称改了 |

看到变化后：

- 同步卡片上会多一行「**3 个接口的内容变了，影响 3 条已关联用例**」+ 一个「看待回归的用例」
- 弹窗按接口列出：改了什么（紫色小标签，鼠标悬停看具体字段名）→ 这条接口挂了哪些用例，**点一下就跳到那条用例的详情**
- 没挂用例的接口只写一句灰字「还没挂用例」，不催、不算待办
- 关掉弹窗也不丢：接口记录页右上角一直有「上次同步变更 · n」，随时能再打开
- 单条接口的详情里还有一行「上次同步变更」，看这条历史上一次改了什么

口径说明：**「上次」永远指最近一次同步**。所以下次同步如果没有任何结构变化，提醒会自己消失（不是漏了，是真没变）。
变更判定完全基于你本地存的上一次快照，不需要联 Apifox、不需要登录态。

### 测试执行（接口测试 / 压测留痕）

Apifox 能跑接口用例（带断言）、能编排测试场景、能压测（虚拟用户 / 时长 / 爬坡 / 实时图表），这些它都比我们强，
所以平台**不碰执行**，只管一件事：**跑完的结果别丢**。

- 「测试执行」里一条记录 = 一次跑批，选类型（接口测试 / 压测），字段跟着类型变：
  - 接口测试：通过 / 失败条数
  - 压测：并发、时长、TPS、P95、错误率
  - 公共：结果（正常 / 异常 / 未判定）、执行时间、场景 / 脚本名、报告链接、结论
- 填完可以**关联接口**，接口详情里就多一块「最近执行」，每行一行摘要：
  `10 并发 · 60s · 320 TPS · P95 180ms · 错 0.2%`、`11 通过 · 2 失败`，绿点 / 红点一眼看出挂没挂
- 接口详情里点「**记一笔**」直接跳到新增表单，接口、环境、时间都预填好了
- 什么都没填的指标不显示，空着也不催 —— 记一笔只需要「哪个接口、跑没跑过、结论是啥」

为什么值得单独记：Apifox 的报告会被下一次跑覆盖，而「这个接口历史上压过几次、最好多少、这次是不是变慢了」只有留在本地才翻得到。

安全相关：

- 启动密码（scrypt 加盐哈希，存本机）
- 闲置 1/5/10/30 分钟自动锁定，可关闭
- 复制密码后剪贴板 15/30/60/120 秒自动清空
- 打开网站时自动把该站密码放进剪贴板（设置页可关），配合 `Ctrl+V` 一步登录
- 密码字段：Windows DPAPI（`safeStorage`）加密后落库，数据库文件里搜不到明文
- 每天首次启动自动备份数据库，保留最近 10 份
- 设置页「清除数据」可选择清空**本地备份文件**或**本地数据文件**：删除 `data.db` 后重建空库（含设置和锁屏密码一起重置），确认按钮有 3 秒倒计时，防手滑

## 怎么用

1. 解压 `测试工作台-0.15.0-win64.zip`
2. 双击 `测试工作台.exe`
3. 首次运行 Windows 会提示「未知发布者」（exe 未签名）→ 更多信息 → 仍要运行

热键 `Ctrl+Alt+T` 唤起窗口。

### 数据放哪

默认 `%APPDATA%\测试工作台\`

```
data.db     主数据（SQLite，密码字段密文）
backups\    自动备份，保留 10 份
runtime\    Chromium 运行时缓存
```

想做成 U 盘便携版：在 exe 同目录新建一个空文件 `portable.marker`，数据就改存 `exe目录\data\`。

设置页可以「打开数据目录」「立即备份」「导出/导入 JSON」——导出默认**不含密码**，要含明文得在弹框里二次确认。

### 备份、恢复与搬家

两种格式，用途不同：

| 格式 | 是什么 | 怎么用 | 适合 |
|---|---|---|---|
| `.db`（整库） | `data.db` 的完整拷贝，含记录 + 用例关联 + 设置 + 选项配置 | 备份列表每行有「恢复」；也可以用「导出整库」存到别处，或导入时直接选 `.db` | **回滚**：升级出问题、误删、想退回昨天 |
| `.json` | 可读的合并包，带原 `id`、用例关联和选项配置 | 「导出」→ 新机器「导入」 | **搬家**：换电脑、交接、备份到网盘 |

关键区别：

- 导入 `.db` = **整库覆盖**（会弹红色确认框，显示文件路径和记录数，恢复前自动给当前库留一份 `data-before-restore-*.db`）
- 导入 `.json` = **合并**（保留原 id，所以用例↔接口的关联能一起挂回去；同一份文件重复导入是原地更新，不会翻倍）
- `.db` 里的密码是 Windows DPAPI 密文，**换机器/换账户解不开**；`.json` 选「含密码」导出的是明文，导入时用新机器的密钥重新加密

### 清除数据

设置 → 数据与备份 → 清除数据，下拉二选一：

| 选什么 | 删什么 | 后果 |
|---|---|---|
| 本地备份文件 | `backups\` 下所有 `.db` | 历史备份没了，`data.db` 不动 |
| 本地数据文件 | `data.db`（删完重建空库） | 全部记录、接口镜像、用例关联、**设置和锁屏密码**一起重置，回到首次启动状态 |

确认按钮 **3 秒后才可点**（标红），防止手滑一步清空。清除不可撤销，重要数据先导出。

## 更新会不会丢数据

不会。数据存在 `%APPDATA%\测试工作台\`，不在软件安装目录里，升级只要替换 exe（或解压新版覆盖），
数据库原地不动。数据库里还记着 `schemaVersion`（设置页「关于」能看到），启动时自动对齐：

| 改了什么 | 老数据会怎样 | 需要做什么 |
| --- | --- | --- |
| 只加新字段 | 老记录该字段为空，界面正常显示 | 不用管 |
| 只加新集合 / 新工具 | 完全不受影响 | 不用管 |
| 字段改名、集合改名、加密方式调整 | 需要迁移 | 版本号 +1，在 `electron/migrations.js` 加一条迁移 |
| `records` 表结构变化 | 需要迁移 | 同上 |
| 新增一张跟记录有关的表（如关联表） | 新表建好，老数据不动 | 版本号 +1，在 `MIGRATIONS` 加一条 |
| 接口镜像那些新字段（模块/描述/Schema…） | 只加 JSON 里的字段，老记录取出来是空值 | 不用管（0.8.0 就没动版本号） |

现有迁移：

| 版本 | 做了什么 |
| --- | --- |
| v2 | 测试账号新增「环境」字段：按所属站点自动回填；没有关联站点的归到「其他」 |
| v3 | 新增用例 ↔ 接口关联表 `case_api_links`（只建表 + 唯一索引，不动任何记录） |
| v4 | 环境 / 角色改多选：老数据里的字符串转成数组，并把历史环境值、角色、标签收进选项配置 |

迁移流程（`electron/migrations.js` + `store.init`）：

1. 启动时比较数据库里的 `schemaVersion` 和代码里的 `SCHEMA_VERSION`
2. 落后就先自动复制一份 `backups\data-before-v{旧版本}-{时间}.db`（这份不会被「只留 10 份」轮转掉）
3. 按版本号从小到大执行迁移脚本，每条跑完立即落盘并推进版本号
4. 任何一条抛错就中止并写 `debug.log`，原库和迁移前备份都还在，可以直接回退
5. 保存记录时会保留 schema 里已不存在的字段——就算某个版本删了字段，编辑一次也不会把它悄悄抹掉

迁移动作用例（v1 → v2 环境回填，再注入一条 v4 把 `account` 改名 `username`）写在 `migrations.js` 的注释里；
`npm run test:migrate` 会造一个 v1 老库、按真实版本号跑一遍，验证升级 / 备份 / 未知字段保留。
注入的假迁移版本号必须大于 `SCHEMA_VERSION`，否则会跟真实迁移撞号。

### 发版流程

**每次发版必须升版本号**，否则会覆盖同名产物、Release 上分不清新旧。

```bash
# 1. 升版本号（三处要一致：package.json / README 引用 / git tag）
#    改 package.json 的 version，例如 0.23.0 → 0.24.0

# 2. 跑测试
npm test

# 3. 打两个产物
npm run dist:installer  # → release/test-tool-Setup-X.Y.Z-x64.exe（约 119 MB）
npm run package:docs    # → release/test-tool-docs-X.Y.Z.zip（约 1.2 MB）

# 4. 提交 + 打 tag
git add -A && git commit -m "chore: 版本 X.Y.Z"
git tag -a vX.Y.Z -m "vX.Y.Z: 一句话说明"
git push origin main
git push origin vX.Y.Z

# 5. 上传到 GitHub Release
#    网页：Releases → Draft a new release → 选 tag → 拖入两个文件
#    或 gh CLI：gh release create vX.Y.Z release/*.exe release/*.zip
```

**产物说明**：

| 文件 | 大小 | 特点 |
|---|---|---|
| `test-tool-Setup-X.Y.Z-x64.exe` | 119 MB | **主下载**：安装向导，per-user 装到 `%LOCALAPPDATA%\Programs`，**不需要管理员**；装完启动 1-2 秒 |
| `test-tool-docs-X.Y.Z.zip` | 1.2 MB | 文档包：README + 17 张界面截图 + 交接文档（含 34 条踩坑笔记） |

**为什么不再发便携 zip**：便携版每次启动要自解压 350MB 到 `%TEMP%`（3-8 秒），
而且 splash 图在双显示器 + 高 DPI 环境下会导致启动失败。安装包是「装一次，之后直接跑」，
没有这些问题。

**为什么产物名是英文**：GitHub Release 上传中文文件名会被截断
（实测 `测试工作台-0.21.0-win64.zip` → `-0.21.0-win64.zip`）。
exe 内部的 `ProductName` 仍是「测试工作台」，用户看到的应用名不变。

**数据位置**：

| 内容 | 位置 | 卸载时 |
|---|---|---|
| 程序文件 | 安装目录（向导里可选，默认 `%LOCALAPPDATA%\Programs\测试工作台`） | 删 |
| 数据库 | `%APPDATA%\测试工作台\` | 保留（除非卸载时勾选删除） |
| 用户资产 | `文档\测试工作台\{test_cases,jmx,压测报告,知识库,notes}` | 保留（除非卸载时勾选删除） |

**卸载时会问你要不要删数据**：卸载向导最后多一页，勾选框「同时删除上述用户数据」，
**默认不勾选**。勾选后显示红色警告 + 二次确认框，列出会删什么。

### 加一个集合

改 `shared/collections.js`，加一段 schema（字段类型支持 text / url / secret / select / textarea / code / markdown / date / datetime / number / link），
界面侧边栏、表格、详情、编辑表单会自动出现，不用写组件。

字段还可以带几个开关：

| 开关 | 作用 |
| --- | --- |
| `formHidden` | 编辑表单里不出现（给同步来的镜像字段用） |
| `hideInDetail` | 详情里不出现（内部快照） |
| `hideEmpty` | 值为空时整行不显示（没有就不占地方） |
| `onlyFor: { kind: 'perf' }` | 只在某个类型下出现（「测试执行」靠它：压测看并发，接口测试看通过率） |

加完跑一次 `npm run test:main` —— 它会自检「titleField / listFields / linkTo / onlyFor 是否都指向真实存在的字段」，
写错一个 key 这里就红。

## 关联字段：测试账号的「所属站点」

「所属站点」不是让你再抄一遍地址，而是一条**指向「网站管理」里某条记录的引用**：

- 账号里存的是那条站点记录的内部 id，界面显示时才解析成站点名称
- 好处是站点改名后账号里自动跟着变，不用两处维护
- 下拉是**平铺按环境排序**的，每条都带「· 环境」后缀（如 `BOSS · 生产`），同名站点一眼分开
- 选完站点会**自动把环境填到账号的「环境」字段**，这个字段会显示在列表里，也能用来筛选
- 「复制整条」输出的也是可读名称，不是 id
- 如果那条站点被删了，账号里会显示「（关联记录已删除）」，重新选一个即可

## 已知限制

- **浏览器里不能自动填密码**：操作系统层面禁止一个程序往另一个程序的窗口里「打字」，所以「打开网站」做的是
  「拉起默认浏览器 + 把密码放剪贴板」，登录框点一下 `Ctrl+V` 即可。真要全自动得在内置浏览器里做（用 webview 自己注入），
  那是另一个量级的活，需要的话再排期
- **未签名**：首次运行被 SmartScreen 拦一次，属正常；公司 EDR 也可能拦
- **SQL 不连库、接口不发请求**：按约定只做「填充变量复制」「复制成 cURL」，需要执行请用 DBeaver / Apifox
- **密码忘记无法找回**：只能删掉 `%APPDATA%\测试工作台\` 重建，备份文件同样加密
- **数据是单机的**：没有多端同步，团队共用需要另做服务端
- **体积**：Electron 本体约 340MB（解压后），压缩包约 150MB；追求小体积可换 Tauri，界面代码可复用
- **同文件同标题的用例算一条**：关联的软键是「文件 + 标题」，现有用例里 2865 条中有 13 对同文件同名（都在
  「生产快速回归执行单」这类文件里，标题是「通用框架」「设备管理」这种）。这类标题挂上关联后，同名的几条会一起显示；
  真要精确到某一条，得给用例改个有区分度的标题
- **接口镜像只认 OpenAPI 3**：Swagger 2.0 的文件会明确报「请在 Apifox 里重新导出为 OpenAPI 3」，不会悄悄少字段；
  单个文件超过 40MB 也会拒绝（先在 Apifox 里只导出要测的目录）
- **同 method+url 的重复记录不会自动合并**：如果你手写过一条、Apifox 里又有同一条，同步认的是先出现的那条。
  看到两条一样的，删掉多余的那条再同步一次就行（同步只认第一条）
- **镜像的是快照**：不做定时拉取，Apifox 更新了要自己再导一次；不做平台内调试器（复制 cURL 去 Apifox 发）
- **变更 diff 只比顶层结构**：参数、请求体/响应体的第一层字段（响应是数组会往里钻一层）、必填清单。
  再深一层的嵌套对象变化（`data.list[].status` 这种）目前不细比 —— 比到了会满屏噪音，真要精确看 Schema 原文
- **diff 依赖上一次的快照**：手写接口第一次被同步时，没有旧快照可比，那一轮不算变更（否则每条都报「全变了」）；
  单条接口的变更最多列 8 项，防止一个字段大改刷屏
- **变更提醒不持久**：「上次同步」永远指最近一次，下次同步没变就自动消失；不做「已读/未读」状态（多一个状态就多一处 bug）
- **用例目录树只有两层**：按「文件所在目录」分组，目录再深（`a/b/c`）也当成一个一级节点显示全路径，不在侧栏里递归展开。
  现有用例库就是「一层需求目录 + 若干 md」，真出现多层再改
- **测试执行只是账本，不是执行器**：不触发 Apifox、不跑压测、不解析报告，结果和指标都是手动填的
  （CLI 触发归档是下一档，得先确认你们环境里 CLI 能连上 Apifox）
- **灰字候选只是「猜」，不是「找」**：靠关键词包含匹配（名称 > 模块 > 描述 > URL 路径），同一个意思换个说法就匹配不上
  （比如用例标题写「退钱」，接口叫「退款」）；最多给 5 条，分数不到阈值宁可不给。反向（在用例详情里推可能相关的接口）
  目前不做 —— 2865 条用例的「候选接口」界面会比接口侧更难收敛
